# 哈喽卧得 iPhone 可试用 MVP 验收标准

版本：V1 · 2026-07-18

本文件定义当前自主开发阶段的终点。只有以下 P0 条件全部通过，才能称为“可以在手机上试用的 MVP”。视觉精修、App Store 正式上架和商业化功能不属于本轮完成条件。

## 1. 产品范围

首版是一个原生 SwiftUI iPhone App，同时支持两类行为：

- 发布者：浏览、发布心愿、获得公开编号、查询进度、查看交付。
- 在场响应者：浏览公开心愿、查看详情、提交响应，等待人工确认。

运营审核和派单继续使用现有 MVP 运营工具；消费者 App 中不得出现运营后台或管理员入口。

## 2. 必须跑通的真实纵向闭环

### P0-A：读取公开心愿

1. App 启动后通过 HTTPS 请求生产兼容 API。
2. 首页和“附近”页显示 `/api/wishes` 返回的真实公开心愿。
3. 支持加载、空数据、服务器错误和断网状态。
4. 公开卡片不显示发布者姓名、联系方式或响应者联系方式。

### P0-B：发布心愿

1. 三步原生表单收集场景、城市、地标、正文、交付方式、期望时间、感谢金、称呼、联系方式和联系同意。
2. 客户端进行必填、长度、金额和同意状态校验。
3. 通过 `POST /api/wishes` 提交真实数据，不使用本地模拟成功。
4. 成功页显示后端返回的公开编号，并可复制。
5. 失败时保留用户已填写内容，可重试，不闪退。

### P0-C：提交响应

1. 从心愿详情进入响应表单。
2. 收集响应者称呼、联系方式、补充说明和联系同意。
3. 通过 `POST /api/wishes/{id}/responses` 提交。
4. 成功页明确说明“等待运营确认，不代表已经接单”。

### P0-D：查询进度和交付

1. 使用公开编号和发布时联系方式调用 `POST /api/wishes/track`。
2. 显示当前状态、心愿摘要、状态时间线和已匹配响应者称呼。
3. 有交付内容时可通过后端返回的 HTTPS 能力链接查看照片或视频。
4. 编号错误、联系方式不匹配、链接失效和网络失败都有明确提示。

## 3. 导航与设计

- 使用 5 栏原生 Tab Bar：首页、附近、发布、进度、我的。
- UI 以 `docs/ios-ui-design-brief.md` 和最终冻结的 Claude 设计交接为准。
- 必须使用系统安全区、Dynamic Type 基础支持和至少 44 × 44 pt 点击区域。
- P0 页面必须有正常、加载、空数据、错误、禁用和提交中状态。
- 不要求本轮完成深色模式，但颜色和组件结构不得阻碍后续支持。
- 不使用简单 `WKWebView` 包装历史网页。

## 4. 客户端技术边界

- 最低系统目标暂定 iOS 16；首次真实 Xcode 构建后再确认是否需要上调。
- 使用 SwiftUI 和系统框架；首版不引入非必要第三方依赖。
- 网络层使用可替换的 API Client，不允许 View 直接散落硬编码请求。
- JSON 模型必须与现有后端字段和枚举严格映射。
- 生产 API Base URL 可配置，发布构建不得指向 `chatgpt.site`。
- UI Preview 可以使用 Mock，但运行时核心流程不得读取 `Wish.mockWishes` 或伪造成功结果。
- 不在 App 内写入 Cloudflare 管理密钥、运营 PIN、数据库凭据或其他服务器秘密。
- 管理员 API `/api/admin/*` 不得出现在消费者 App 中。

## 5. 最低工程质量

- 完整 Xcode 环境下 Debug 构建成功，零编译错误。
- 至少覆盖公开列表解码、发布请求编码、响应请求编码和进度解码的单元测试。
- 核心流程不使用强制解包、`try!` 或吞掉错误的空 `catch`。
- 网络请求支持取消或避免重复提交；提交按钮在请求期间禁用。
- 表单和状态切换没有明显数据丢失、重复跳转或主线程阻塞。
- App Icon、Bundle ID、版本号和隐私用途说明具备可安装测试所需的基本配置。

## 6. 模拟器与真机验收

### 模拟器

- 在至少一个常见 iPhone 模拟器上冷启动成功。
- 完成公开列表、发布、响应和查询进度的真实 API 联调。
- 旋转锁定为竖屏时布局正常；键盘不遮挡关键提交按钮。

### 真实 iPhone

- 使用产品负责人的 Apple 账号 Personal Team 或 TestFlight 安装。
- 从主屏幕图标冷启动，不依赖开发者电脑上的本地服务器。
- 在 Wi-Fi 或移动网络下访问 Cloudflare 生产兼容 API。
- 使用非真实隐私测试信息跑通发布、运营审核/派单、进度查询和交付查看。
- 记录设备型号、iOS 版本、构建号、测试单号和发现的问题。

## 7. 本轮明确不做

- App Store 正式提交和商店审核。
- Apple 登录、完整账户系统和跨设备同步。
- Apple Push Notification 推送。
- Apple Pay、应用内购买、退款和平台抽成。
- 原生运营后台。
- 自动派单、聊天、评价、复杂地图和多城市算法。
- iPad、Mac、Android 和网页消费者端。

这些功能进入后续里程碑，不得阻塞手机可试用 MVP。

## 8. 完成证据

完成时必须在 `PROJECT_LOG.md` 记录：

1. 最终提交和构建号。
2. Xcode、Swift、iOS SDK 和模拟器版本。
3. 自动化测试命令及结果。
4. 真实 API 测试单号。
5. 真机型号、系统版本和安装方式。
6. 已知但不阻塞试用的问题。
7. 下一阶段建议，不自动扩大本轮范围。
