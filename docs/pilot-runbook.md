# 哈喽卧得 MVP 试运营手册

这份手册用于首批 10–30 位真实用户的小范围试运营。目标不是追求自动化，而是验证：是否有人愿意发布心愿、供应者能否稳定履约、发布者是否愿意为结果付费。

## 上线前最低条件

- 录入至少 3 位能稳定联系到的种子响应者，其中至少 2 位当前可接单。
- 用非真实隐私信息完整跑通至少 1 笔测试单：发布、审核、匹配、接单、交付、确认完成。
- 检查公开页面不会显示发布者或响应者的联系方式。
- 确认运营 PIN 只由核心运营人员保管，运营导出文件不通过公开链接分享。
- 准备一个可随时联系的人工客服入口，并约定退款与异常处理口径。
- 若从微信小程序进入试运营，还必须完成 `docs/wechat-mini-program-launch.md` 的主体、服务域名、隐私指引、体验版和登录换码清单；未通过微信控制台审核前，不得称为已上线。

## 每一单怎么处理

1. 发布者提交心愿后，订单进入“待审核”。
2. 运营人员检查内容是否合法、可执行、没有明显隐私或安全风险。
3. 审核通过后，订单进入“待匹配”；优先从同城供应者名册中选择。
4. 联系供应者确认地点、时间、交付形式和感谢金，再在后台记录派单。
5. 供应者确认后标记“已接单”，开始履约。
6. 供应者提交照片或短视频后，由运营人员上传或记录 HTTPS 交付链接。
7. 发布者确认收到后，将订单标记为“已完成”。
8. 发生爽约、地点不可达或内容不合适时，记录原因并退回匹配或取消。

9. 使用小程序账户的发布者可在“我的”读取交付并确认完成；如需注销，用户可在“我的”发起删除账户。注销会撤销登录和匿名化个人资料，不得用旧联系方式重新登录或冒领。

## 每日运营节奏

- 上午和傍晚各清一次待审核队列，真实试运营阶段尽量在 4 小时内响应。
- 每次派单前确认供应者仍可接单；不要仅依赖名册里的历史状态。
- 每晚导出一次运营表，存入仅核心团队可访问的位置。
- 对所有未完成订单做一次人工追踪，优先处理已经超过约定时间的订单。
- 对外沟通只使用订单公开编号，不在群聊或公开表格中暴露联系方式。

## 首批需要记录的指标

- 发布心愿数、审核通过率。
- 从审核通过到找到供应者的中位时长。
- 接单率、按时交付率、最终完成率。
- 每单人工沟通次数与运营耗时。
- 发布者愿意支付的金额、供应者可接受的金额。
- 退款、投诉、安全事件和主要失败原因。

## 暂停试运营的红线

- 出现人身安全、骚扰、未成年人、违法内容或明显隐私泄露风险。
- 交付文件被无关人员访问，或运营 PIN、导出文件发生泄露。
- 连续出现无法履约且无法及时联系发布者的订单。

遇到红线时，先暂停新增真实订单，保留记录并处理受影响用户；稳定的 GitHub Pages 演示版可以继续用于展示，不承接真实数据。
