# iOS MVP 视觉方向 v3

状态：`USER-DIRECTED / CL-003 IN PROGRESS`
日期：2026-07-18（Asia/Shanghai）

本文件记录用户查看实际预览后的最新视觉裁决，优先级高于 `docs/ios-design-freeze-v1.md` 中的视觉 Token。旧版的信息架构、业务状态与隐私约束仍可复用，但不得直接照搬旧版视觉。

## 核心感受

- 温暖、柔和、可信、有人情味，但不甜腻、不幼稚。
- 参考 Airbnb 的内容主导、留白、触感和亲和力；只学习原则，不复制布局、商标或品牌资产。
- 产品界面保持安静克制，让用户交付的照片和视频成为最鲜艳、最有情绪的内容。
- 避免课程作业感、网页后台感、过度工具化和大面积冷硬黑白。

## 绝对禁止

1. App Icon、Tab、按钮、空状态、提示、列表、帮助页和任何应用内界面都不得使用 Emoji 字符或 Emoji 风格图形。
2. 不得使用渐变，包括背景、按钮、卡片、图标和遮罩。
3. 不得使用花哨的多色品牌装饰、大面积高饱和色、玻璃拟态、霓虹、3D 插画或重投影。
4. 不得复制 WhatsApp、X、Threads、Instagram、Airbnb 的商标轮廓或受保护图形。

## Icon 原则

- App Icon 参考 WhatsApp、X、Threads、Instagram 的设计原则：轮廓简单、中心符号单一、20–60pt 仍清晰、黑白剪影可识别；必须是哈喽卧得原创几何标志。
- App Icon 不放文字、不放 Emoji、不用渐变，最多使用一个底色和一个前景色。
- 提供 3 个原创方向及 20、29、40、60、1024pt 小尺寸测试；Claude 推荐一个主方案，并解释如何抽象表达“远方、抵达、在场”。
- App 内功能图标在设计稿中使用统一单色矢量线性图标；SwiftUI 实现优先使用 SF Symbols。禁止用字符 Emoji 代替图标。
- 图标线宽、圆角端点、视觉尺寸和对齐方式必须统一。

## 色彩

- 暖中性色承担大部分界面，品牌色只用于主动作、选中、焦点和少量状态。
- 不用渐变。层级优先依赖留白、字号、字重、暖灰表面和 hairline，而不是色块堆叠。
- 旧品牌蓝可作为候选强调色，但必须验证其在暖背景上是否柔和；如建议调整，只提交一个克制替代方案与旧蓝并排比较，不扩展多套彩色主题。
- 用户上传的照片、视频和交付内容应成为页面最丰富的色彩来源；产品 chrome 不与内容争夺注意力。

## 卡片与形状

- 卡片圆角是品牌触感的重要组成，必须系统化，不得每页随意变化。
- 明确小控件、输入框、普通卡片、重点卡片和 Bottom Sheet 的圆角值与适用条件。
- 卡片以暖白或浅暖灰表面、细描边和留白建立层级；原则上无阴影，如确需阴影只能极轻并注明条件。
- 胶囊只用于筛选标签或确实需要的主动作，不把所有控件都做成胶囊。

## 字体

- 字体、字号、行高和字重逐级定义，并映射 iOS Dynamic Type 语义样式。
- 页面标题、卡片标题、正文、辅助信息、金额、按钮和表单标签各自只使用固定层级，不得同类元素字号漂移。
- 正文以舒适阅读为先，避免满屏粗体；主要使用 Regular、Medium、Semibold，Bold 只用于极少数关键标题。
- 验证中文行高、卡片内文本宽度和 AX3 Dynamic Type；核心信息不可被截断。

## 验收

- 人工逐屏确认没有 Emoji、没有渐变、没有复制品牌图形。
- HTML/CSS 搜索 `gradient` 应无命中；可访问文本不得出现 Emoji 字符。
- 20pt App Icon 仍能辨认核心轮廓。
- 卡片圆角与字体层级可在 Foundations 中逐项追溯。
- 页面结构继续遵守公开/私有数据边界和 `docs/ios-api-contract.md`。
