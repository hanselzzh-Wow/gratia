# 哈喽卧得 iOS UI 设计任务书

版本：V1 · 2026-07-17
用途：可直接转发给 UI 设计师。设计完成后将平面界面图、组件规范和独立素材交回开发，用于 SwiftUI 实现。

## 1. 产品与本次设计目标

哈喽卧得帮助用户委托远方当地的人，到指定城市和地标完成一件小心愿，例如录制祝福视频、为景色配音或制作手写卡片。

本次设计的是原生 iPhone App，不是网页，也不是把网页套进手机壳。一个 App 同时服务两类行为：

- 发布者：发布心愿、留下联系方式、获得编号、查询进度、查看交付。
- 在场响应者：浏览附近心愿、查看详情、提交响应，等待人工确认匹配。

首版仍采用人工审核和人工匹配。不要在界面中表现为“点击后立即自动接单”。

## 2. 视觉方向

### 核心感受

温暖、可信、轻盈、有距离感但不疏离。关键词：远方、抵达、城市、信件、路径、善意、真实的人。

### 建议视觉语言

- 主色：清透天空蓝，可参考现有品牌蓝，但降低网页感和高饱和渐变。
- 强调色：少量暖黄色或晨光金，用于“心意”和关键完成状态。
- 文字：深海军蓝或接近黑色，正文要有足够对比度。
- 背景：偏暖白，不要大面积冷灰。
- 图形：路线、坐标点、信封、城市轮廓、柔和天空与晨光。
- 卡片：克制的圆角和极轻阴影，以原生层级和留白为主。
- 字体：优先使用 iOS 系统字体与苹方，必须支持 Dynamic Type。

现有 `public/og.png` 可作为“天空、远方、信件、城市坐标”的情绪参考，不要求照搬。现有 `public/hlwd.png` 只作为早期概念参考，设计师需要重新整理适合 App Icon 和小尺寸使用的简洁标志。

### 避免

- 不做旅游订票、跑腿平台或金融 App 的强交易感。
- 不使用过量玻璃拟态、荧光渐变、3D 装饰和悬浮卡片。
- 不把长段文字烘焙进插画。
- 不用只有装饰意义的地图；当前后端没有经纬度，V1 不设计真实地图模式。
- 不要把手机外框、透视样机或环境背景当作开发交付图。

## 3. 画板与基础规范

- 设计对象：竖屏 iPhone。
- 基准画板：393 × 852 pt；同时考虑 375–430 pt 宽度自适应。
- 内容水平边距：建议 20 pt；密集列表可使用 16 pt。
- 间距体系：4/8 pt 网格。
- 所有可点击区域至少 44 × 44 pt。
- 正文默认不小于 15–17 pt；辅助文字不小于 12 pt，并保证对比度。
- 使用系统安全区、系统状态栏和 Home Indicator。
- 首轮只需完整交付浅色模式，但颜色 Token 要能扩展到深色模式。
- 优先使用 SF Symbols；自定义图标需单独交付 SVG/PDF 矢量文件。

## 4. 全局信息架构：底部 5 栏

| 位置 | 名称 | 功能 | 图标建议 |
| --- | --- | --- | --- |
| 1 | 首页 | 品牌入口、角色引导、推荐心愿和流程说明 | `house` |
| 2 | 附近 | 按城市浏览公开心愿、筛选、进入详情 | `location` |
| 3 | 发布 | 创建新心愿，视觉上最突出 | `plus.circle.fill` |
| 4 | 进度 | 查询我发布的心愿及交付状态 | `clock.arrow.circlepath` |
| 5 | 我的 | 个人状态、帮助、安全、隐私和设置 | `person` |

中间“发布”可以使用品牌强调色和略强的视觉权重，但保持标准 Tab Bar 行为，不设计脱离系统逻辑的大型悬浮按钮。

## 5. 三条必须完整覆盖的用户流程

### A. 发布心愿

首页/发布栏 → 三步发布表单 → 确认摘要 → 提交中 → 发布成功 → 保存公开编号 → 进入进度。

### B. 响应心愿

附近 → 心愿详情 → “我刚好在这里” → 填写称呼、联系方式和说明 → 同意联系 → 提交成功 → 等待运营确认。

### C. 查询和接收交付

进度 → 输入公开编号和发布时联系方式 → 状态详情 → 时间线 → 查看照片/视频交付 → 完成状态。

## 6. 页面清单与区域排布

### 00 启动页

从上到下：

1. 大面积安静背景，可使用天空、路径或城市晨光的抽象图形。
2. 居中品牌标志与“哈喽卧得”。
3. 副标题：“让想说的话，抵达远方。”
4. 底部很轻的加载状态；不要放按钮。

### 01–03 首次引导（同一模板三页）

每页固定结构：顶部跳过 → 中部独立插画区约 45% → 标题 → 两行说明 → 页码圆点 → 底部主按钮。

三页内容：

1. “把心意送到远方”——发布城市、地标和想说的话。
2. “让恰好在场的人帮你抵达”——由真实响应者完成。
3. “人工确认，过程可追踪”——强调审核、隐私和交付。

### 10 首页

```text
┌─────────────────────────┐
│ 城市选择      品牌      通知 │ 顶部栏
│                         │
│      品牌主视觉卡片          │ 约 170–190 pt
│  一句话价值 + 发布心愿按钮     │
│                         │
│ [我要发布]  [我能帮忙]        │ 双入口
│                         │
│ 附近正在等待的心愿       查看全部 │
│ [横向心愿卡] [横向心愿卡]      │
│                         │
│ 如何完成：发布→匹配→抵达       │ 三步说明
│ [人工审核与隐私说明条]          │
├─────────────────────────┤
│ 首页  附近  发布  进度  我的   │
└─────────────────────────┘
```

区域要求：

- 顶部栏：当前城市选择器、简洁品牌、通知入口占位。
- 主视觉：一句价值主张、短说明、主按钮“发布一个心愿”。
- 双入口：“我要发布”和“我刚好在这里，可以帮忙”。
- 推荐心愿：展示 2–3 张横向卡片，卡片内容见下文。
- 三步流程：发布心愿、人工匹配、现场交付。
- 信任条：说明联系方式不公开、内容先审核、异常可联系客服。

### 20 附近心愿列表

从上到下：

1. 大标题“附近的心愿”与当前城市。
2. 搜索框，占一整行；搜索地标或关键词。
3. 横向筛选胶囊：全部、城市、交付方式、期望时间、感谢金。
4. 结果数量和排序入口。
5. 纵向心愿卡列表。
6. 固定底部 Tab Bar。

心愿卡固定内容层级：

1. 城市 · 地标；右侧感谢金。
2. 场景标签、交付方式标签。
3. 心愿正文最多三行。
4. 期望时间；右侧“查看详情”。

不能出现发布者姓名、联系方式或精确住址。

### 21 筛选底部弹层

- 顶部拖拽条、标题和“重置”。
- 城市单选或多选区域。
- 交付方式：口播视频、景色配音、手写卡片。
- 期望时间和感谢金区间。
- 底部固定主按钮“查看结果”。

### 22 心愿详情

```text
┌─────────────────────────┐
│ 返回       城市·地标       分享 │
│ [城市氛围图/抽象路线视觉]       │ 160–200 pt
│ 待匹配标签             ¥18     │
│ 场景标题                        │
│ 心愿正文大卡                    │
│ 交付方式 / 期望时间              │
│                         │
│ 这次帮助如何完成：三步           │
│ 安全与隐私说明                   │
│                         │
│ [我刚好在这里，可以帮忙]         │ 固定底部
└─────────────────────────┘
```

详情页不显示发布者身份。CTA 下方注明：“提交响应后由运营人员确认，不会自动接单。”

### 23 提交响应底部弹层

从上到下：拖拽条 → 地标摘要 → 称呼 → 微信或手机号 → 补充说明 → 联系同意勾选 → 主按钮“提交响应”。

补充说明示例：“周六下午在外滩附近，可以拍 30 秒视频。”设计正常、聚焦、错误和提交中状态。

### 24 响应成功

- 成功图形。
- 标题“已收到你的响应”。
- 说明“运营人员确认后会联系你，这还不代表已经接单”。
- 心愿摘要卡。
- 主按钮“继续看看”，次按钮“返回首页”。

### 30–32 发布心愿：三步表单

三屏共用结构：

```text
┌─────────────────────────┐
│ 关闭      发布一个心愿      帮助 │
│ 步骤 1/3  ━━━━━○○             │
│ 标题 + 一句解释                 │
│                         │
│ [本步骤表单内容，可滚动]         │
│                         │
│ [返回]          [继续/确认]      │ 固定底部
└─────────────────────────┘
```

步骤 1“想送到哪里”：

- 心愿场景：生日祝福、加油鼓励、毕业祝福、浪漫表白、节日问候。
- 城市。
- 地标。

步骤 2“想让对方收到什么”：

- 想说的话，最多 120 字，显示字数。
- 交付方式三选一：口播视频、景色配音、手写卡片；每项要有图标和一句解释。
- 期望完成时间。

步骤 3“确认与联系”：

- 感谢金：¥12、¥18、¥28，允许设计为选择卡，不表现为已完成支付。
- 发布者称呼。
- 微信或手机号，明确“仅运营可见”。
- 联系同意勾选。
- 提交前摘要：城市、地标、交付方式、期望时间和感谢金。

每一步都要设计键盘出现、字段错误、按钮禁用和提交中状态。用户返回上一步时内容不能丢失。

### 33 发布成功

- 成功主视觉。
- 标题“心愿已送出，正在等待审核”。
- 公开编号使用醒目等宽数字样式，例如 `HW260717-ABCDE`。
- “复制编号”与“保存到照片”两个动作。
- 六步简化状态：已提交、审核中、匹配中、已接单、已交付、已完成。
- 主按钮“查看心愿进度”，次按钮“返回首页”。
- 提醒用户编号和联系方式共同用于查询，不要公开转发。

### 40 进度首页

未登录的 V1 结构：

1. 标题“心愿进度”。
2. 说明卡：编号可在发布成功页找到。
3. 公开编号输入框。
4. 发布时联系方式输入框。
5. 主按钮“查询进度”。
6. 最近查询占位区域；无记录时显示安静空状态。
7. “编号找不到？”帮助入口。

### 41 进度详情

- 顶部状态大卡：当前状态、城市、地标、公开编号。
- 心愿摘要：内容、交付方式、期望时间、感谢金。
- 纵向时间线：已提交、审核、匹配、接单、交付、完成。
- 匹配后才显示响应者称呼，不显示私人联系方式。
- 有交付时显示照片/视频预览卡和“查看交付”。
- 底部帮助入口。

另做“未通过”和“已取消”两种异常状态，使用克制的提示色，不使用恐慌式红色大面积背景。

### 42 交付预览

- 全屏照片或视频区域。
- 顶部关闭、心愿编号和分享入口。
- 底部半透明信息层：交付说明、时间、响应者称呼。
- 预留“内容有问题”入口。

### 50 我的

V1 同时设计未登录与未来登录后两种状态：

- 头像/品牌占位、称呼或“登录后同步心愿”。
- 我的发布、我的响应两个数据入口；未登录时引导使用编号查询。
- 通知设置。
- 帮助与客服。
- 安全中心。
- 隐私政策、用户协议、关于哈喽卧得。
- 版本号。

不要在消费者 App 中出现运营后台入口。

### 51 帮助与安全

- 安全原则：只接受合法、善意、可安全执行的请求。
- 隐私说明：联系方式不公开，仅用于审核、匹配和履约。
- 常见问题列表。
- 联系客服按钮。
- 举报/投诉入口。

## 7. 必须设计的通用状态

以下不是开发自行猜测的内容，设计稿中必须提供组件或页面状态：

- 骨架加载。
- 无心愿空状态。
- 断网和服务器错误。
- 表单字段错误。
- 按钮默认、按下、禁用、加载。
- Bottom Sheet 展开。
- Toast、成功和错误提示。
- 照片/视频加载失败。
- 联系方式等敏感信息的隐私提示。
- Dynamic Type 放大后的关键页面示例。

## 8. 组件清单

请建立可复用组件，而不是每屏重复绘制：

- 5 栏 Tab Bar。
- Navigation Bar。
- 主按钮、次按钮、文字按钮、危险文字按钮。
- 城市/类型/状态 Chip。
- 心愿卡、摘要卡、信任提示卡、交付卡。
- 单行输入、多行输入、选择器、金额选择卡、复选框。
- 搜索框和筛选 Bottom Sheet。
- 状态标签、横向进度和纵向时间线。
- Empty/Error/Loading State。
- Toast、Alert、Confirmation Dialog。

## 9. 设计师交付物

最低交付要求：

1. 一张页面地图，说明页面之间如何跳转。
2. 上述核心页面的平面设计图，不带手机外框和透视背景。
3. 基准画板 393 × 852 pt；若导出 PNG，建议同时提供 3x 的 1179 × 2556 px。
4. 单独的 Design System 页面：颜色 Hex、字体字号/字重、间距、圆角、阴影、图标名称和组件状态。
5. 自定义插画、Logo、App Icon 与图标作为独立文件交付；不要只嵌在整张截图里。
6. App Icon 提供无圆角的 1024 × 1024 px 主文件。
7. 页面命名统一，例如：
   - `00_Launch`
   - `10_Home_Default`
   - `20_Wishes_List`
   - `22_Wish_Detail`
   - `30_Publish_Location`
   - `33_Publish_Success`
   - `41_Tracking_Detail`
8. 如果只生成图片而没有 Figma，额外提供一张标注图，写清边距、字号、颜色、圆角和组件高度。

## 10. 首轮需要交付的优先级

先交付以下 8 组，用于确认整体方向：

1. App Icon + 启动页。
2. 首页。
3. 附近心愿列表。
4. 心愿详情。
5. 发布三步表单。
6. 发布成功。
7. 进度查询与进度详情。
8. Design System 基础页。

这 8 组确认后，再补首次引导、响应弹层、交付预览、我的、帮助、安全和全部异常状态。
