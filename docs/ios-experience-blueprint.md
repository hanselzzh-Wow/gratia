# 哈喽卧得 iOS 体验蓝图

状态：产品与体验方向；不授权 SwiftUI、后端或数据迁移实现。
版本：v1，2026-07-18（Asia/Shanghai）

## 北极星体验

用户不必先理解平台，才敢表达牵挂或帮助别人。每一步只回答一个自然问题：我看见了什么温暖的事？我现在能做什么？提交后事情是否正在发生？

情绪曲线是：**被故事打动 → 选择行动 → 得到确定反馈 → 看见完成**。内容是主角；界面负责降低犹豫、保护隐私、说明进度。

## Apple 原则的产品翻译

| 原则 | 哈喽卧得的做法 |
| --- | --- |
| 聚焦主任务 | 每屏一个主要行动；次操作进入详情、菜单或下一步。 |
| 系统优先 | 使用原生 TabView、导航、Sheet、表单焦点、返回手势与系统反馈。 |
| 反馈匹配重要性 | 字段错误贴着字段；加载在内容原位；关键成功给结果页；只有高风险操作打断。 |
| 用户控制 | 联系、内容公开、媒体公开分别同意；默认不公开。 |
| 动效解释关系 | 用系统转场说明进入内容、前进和完成；不用自动轮播、持续漂浮或夸张弹跳。 |
| 可及性默认 | Dynamic Type、VoiceOver、降低动态效果、降低透明度、深浅模式与弱网都是正常状态。 |

参考：[Designing for iOS](https://developer.apple.com/design/human-interface-guidelines/designing-for-ios/)、[Materials](https://developer.apple.com/design/human-interface-guidelines/materials)、[Tab bars](https://developer.apple.com/design/human-interface-guidelines/tab-bars)、[Feedback](https://developer.apple.com/design/human-interface-guidelines/feedback)、[Motion](https://developer.apple.com/design/human-interface-guidelines/motion)。

## 五栏分工

| 栏目 | 用户意图 | 主要内容与行动 | 不承担 |
| --- | --- | --- | --- |
| 首页 | 被完成感打动 | 已完成、脱敏且授权的故事；发布／去附近 | 活跃市场、私密订单 |
| 附近 | 找到能帮的事 | 搜索、筛选、详情、真实响应 | 社区故事流 |
| 发布 | 托付一件心愿 | 三步表单、确认、真实编号 | 内容浏览、伪成功 |
| 进度 | 私密了解履约 | 查询、时间线、交付预览 | 公开订单 |
| 我的 | 找帮助和隐私说明 | 访客帮助、安全、以后账户入口 | 运营管理、假登录 |

五栏只负责顶层地点切换，不承担操作；栏目为空时仍可达并解释原因。

## 三条关键流程

### 故事到发布

首页故事按“心愿的一句话 → 如何完成 → 交付片段／感谢”阅读。详情只给两个转化出口：**我也想发布心愿**、**去附近看看能帮什么**。没有公开故事时，用诚实空态和这两个出口，不用假故事或假互动填充。

### 附近到响应

附近只展示真实活跃心愿。详情后才出现简短响应 Sheet：称呼、联系方法、可选说明、独立联系同意。成功页要说明“已收到响应，等待运营确认，不代表已接单”。

### 发布到交付

发布三步为地点与场景、心愿与交付方式、确认；可返回且草稿不丢失。成功后展示真实公开编号和私密查询方式。进度页显示真实时间线；交付预览绝不泄露联系人、能力 URL 或 token。

## 状态与反馈合同

| 场景 | 合适反馈 |
| --- | --- |
| 首次加载 | 内容位骨架或简洁进度；保留导航，禁止白屏。 |
| 空数据 | 解释原因和下一步，禁止伪造推荐。 |
| 字段错误 | 字段下方短文案，回到首错字段，不能只变红。 |
| 网络或限流 | 原位说明、保留草稿、可重试，不能泄露输入。 |
| 成功 | 结果页、真实结果与一个清晰出口，不能只有短 Toast。 |
| 内容公开 | 单独同意、默认关闭、可撤回；联系同意不等于内容公开。 |

## 交互、动效与视觉层

1. iOS 26+ 使用系统 `TabView` 的**浮动 Liquid Glass Dock**，内容可在其下连续滚动；iOS 16–25 保持系统原生 Tab Bar。系统处理收缩、透明度、触控和辅助功能。
2. 故事、心愿和交付媒体用系统 push 或 Sheet；返回保持原上下文。视频默认静止，必须由用户明确播放。
3. 表单前进是轻量连续过渡，后退保留草稿；提交中阻止重复提交，不遮挡主操作。
4. 关键成功可用一次轻触感或短暂 SF Symbol 动效；降低动态效果时移除非必要位移和缩放。
5. 内容层用暖白、正文优先和真实/示意媒体；Glass 仅为导航和少量短暂控制服务，不能进入普通内容卡片。

### 设计系统与动效基线

- 以 8pt 网格组织间距，4pt 只用于图标/基线微调；页面要有足够留白，但不靠巨大空区制造“高级感”。
- 使用 SwiftUI 语义字体与 San Francisco 系统字体；标题、正文、辅助信息都支持 Dynamic Type，不写死不可缩放字号。
- 颜色使用语义 token：浅色模式保留暖白/暖蓝；深色模式使用暖调深灰和系统可读对比，不能简单把页面反相。正文和关键控件至少满足可读对比要求。
- 所有触控目标至少 44×44pt；图标按钮必须有可读名称、焦点状态和 VoiceOver 描述。
- 自定义微动效优先只改变 `transform` 与 `opacity`，通常控制在约 150–300ms；复杂页面转场交给系统。iPhone 不设计网页 hover 状态，也不使用持续缩放、卡片上浮或滚动揭示来抢夺注意力。
- 减少 `backdrop-filter`/Glass 数量；浮动 Tab Bar 使用系统材质，内容卡片不叠加玻璃、渐变和重阴影。

## 内容与社交边界

公开故事必须独立授权、脱敏、可审核、可下架。联系人、精确地点、时限、内部响应者身份、能力链接/token、未经授权媒体和可识别线索默认排除。

点赞是以后温和的鼓励，不是第一轮真机 MVP 的假热度。账户、真实计数、限流、撤回、审核和举报具备之前，不显示伪造点赞数，也不加入关注、私信、评论或好友关系。
