## 采纳为后续候选的内容

1. 首页 Hero 可在后续视觉任务中更简洁：更明确的主标题、一个实心主行动与一个文字次行动。
2. 心愿卡应让正文成为信息重心；地点和感谢金可以降为安静的辅助信息，不能抢占内容层级。
3. 附近页可采用原生 `.largeTitle` 和更清晰的内容优先排版；详情可向更克制的 editorial 正文结构收敛。
4. 用户已明确首页的产品角色：首页不得再次承担完整心愿列表，而应成为内容优先的精选完成案例空间，以“心愿故事 → 我也想发布／我也想帮忙”驱动转化；“附近”保留完整浏览、搜索、筛选、详情与响应；“发布”只承担创建流程。隐私、内容同意、点赞和实施门槛见 `docs/home-community-direction.md`。此项仍不构成当前源码改动授权。

## 不接受进入当前 MVP 的内容

浮动毛玻璃 Dock 及其新增阴影例外不进入当前 MVP。

理由：它与冻结 v3 的原生五栏 Tab Bar 和默认零阴影冲突；仅给选中项展示文字会削弱其余四个目的地的可发现性与无障碍语义；在 P0-D 真实追踪/交付尚未验收时替换底部导航，会扩大视觉与回归测试范围。当前五个目的地和名称保持为：首页、附近、发布、进度、我的。

## 实施前置条件

任何 v3.1 候选实现必须同时满足：

1. `AG-006` 真实追踪与交付通过独立验收并合入 main。
2. 当前完整流程有真实 Simulator 截图与回归结果，作为对照。
3. 新建明确的独立任务，限定可修改路径，禁止改业务 API、后端和签名。
4. 实现须保留五个有文字标签、可访问的原生 Tab Bar 项；支持 Dynamic Type、VoiceOver 与 44pt 最小点击目标。
5. 提供所有受影响页面与状态的真实 Simulator 截图，并经产品负责人和 Codex 复核后才可更新设计冻结。

## 结论

v3 保持唯一实现基线。v3.1 的内容层级思路可作为 P0-D 之后的受控优化输入；浮动 Dock 被明确排除在本轮 MVP 之外。
