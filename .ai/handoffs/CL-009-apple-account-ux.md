## 0. 总原则（冻结）

1. **浏览永远免登录**：首页、搜索、帮助列表/详情、进度查询（旧编号通道）不要求登录。
2. **登录只在"落笔"时点**：发布提交、响应提交、以及使用"我的"归属能力时才要求 Apple 登录；表单可先填后登录，登录成功后回到原地自动继续，不丢草稿。
3. **只有 Apple 登录**：不做手机号/微信登录；联系方式仍只是运营协调信息，**绝不作为登录凭证**。
4. **诚实原则延续**：无内容显示真实空态；不做假记录/假成功；所有"处理中"必须对应真实后端请求。

## 1. 登录时点与 Apple 授权状态处理（交付 1）

### 1.1 触发点

| 场景 | 时点 | 未登录行为 |
| --- | --- | --- |
| 发布心愿 | 第 3 步点「确认并提交」时 | 弹登录说明片（§5 屏 A）→ Apple 原生面板 → 成功后自动继续提交 |
| 响应心愿 | 响应表单点「提交响应」时 | 同上，成功后自动继续提交 |
| 我的-归属列表/找回/删除 | 进入对应功能时 | 显示登录前视图（§2），点「通过 Apple 登录」 |

登录说明片文案（提交前弹出，半高 Sheet）：标题「用 Apple 账号继续」；正文「登录后这个心愿会归属到你的账号，可以随时查看进度，无需再记编号。我们只获取 Apple 提供的基本信息。」；主按钮为 Apple 官方「通过 Apple 登录」黑色按钮（`SignInWithAppleButton`，官方样式不改色）；次按钮「暂不登录」——**发布/响应允许降级**：走现有匿名流程（成功页给公开编号，提示"未登录，请保管编号"），保证 1.0 现有闭环不被登录墙截断。

### 1.2 授权结果矩阵

| 结果 | 处理 | 用户所见 |
| --- | --- | --- |
| 成功（首次） | Apple 只在首次返回姓名/邮箱：**当次立即随登录请求上送 Worker 持久化**；客户端不再假设以后能拿到。姓名缺失→默认昵称"心愿用户-XXXX"（可改） | 回到原动作自动继续，顶部轻提示"已登录" |
| 成功（再次） | 仅 identityToken/userID，服务端查档 | 同上 |
| 用户取消 | 无副作用，回到触发前状态，草稿保留 | 说明片关闭，无错误弹窗 |
| 失败（1000/1004 等） | 保留草稿 | 说明片内红字"登录未完成，请重试"+「重试」「暂不登录」 |
| 网络断开 | 同失败；提交动作不发出 | 文案改"网络不可用，请检查后重试" |
| 凭证撤销（`credentialState == .revoked`，App 启动与前台激活时检查） | 静默清本地会话 → 我的页回登录前态 | 下次进入"我的"见一次性横幅"Apple 登录已失效，请重新登录"；浏览不受影响 |
| `notFound` | 视同未登录 | 无提示 |

## 2. 「我的」信息架构（交付 2）

### 2.1 登录前（= 1.0 现状 + 一个入口）

访客卡改为：头像位 + 「访客模式」+ 副文案「登录后发布和帮助记录自动归属账号」+ Apple 官方按钮（黑，全宽，44pt+）。其下保持现有「我发布的/我帮助的」（编号查询通道原样保留）、服务与支持、关于。**不弹强制登录。**

### 2.2 登录后

```
[账户卡] 昵称（可改）· "Apple 账号已连接" · 隐藏邮箱不展示
[我的心愿]
  我发布的  → 本人发布列表（真实 API，按状态段：等待回应/进行中/已完成——此时 chips 才有数据，兑现 CL-008 P1-3）
  我帮助的  → 本人响应列表（响应状态：待确认/已确认/已完成/未通过）
  找回历史心愿 → §2.4 兼容找回
[服务与支持]（原样）
[账户与安全] 退出登录 · 删除账户
```

列表行 = 城市·地标 + 状态徽章 + 时间；详情复用现有 `ProgressView` 结果页（免输编号，服务端按归属校验）；有交付即现有全屏预览。列表空态："还没有发布过心愿"+「发布一个心愿」真实 CTA。列表状态：loading 转圈/failed 重试/empty/loaded，同帮助页模式。

### 2.3 归属规则

登录状态下发布/响应成功 → 服务端把该记录绑定 `userId`；成功页仍显示公开编号（兼容分享给他人查询），但主文案改"已保存到「我的-我发布的」"。匿名（暂不登录）产生的记录不归属，靠编号查询或事后找回。

### 2.4 兼容找回（防冒领，冻结）

入口：我的-我发布的 →「找回历史心愿」。流程：输入公开编号 + **发布时填写的联系方式** → 服务端做与现有 track 相同的双因子匹配 → 匹配成功即绑定当前账号。规则：①验证强度与现有查询一致，沿用现有限速/429，连续 5 次失败冷却 15 分钟并提示；②每个编号**只能绑定一次**，已绑定的编号再次找回显示"该心愿已归属其他账号，如有异议联系平台"（不透露任何对方信息）；③找回请求中的联系方式即用即清（与现有查询同）；④成功后原编号+联系方式查询通道**仍然可用**（分享查询场景），但绑定关系不可转移。找回页状态：输入校验/提交中/匹配失败（同现有 404 文案口径"请检查编号和联系方式"）/已被绑定/成功（行内出现在列表顶部并高亮一次）。

## 3. 退出登录与删除账户（交付 3）

### 3.1 退出登录

「账户与安全→退出登录」→ 系统确认弹窗「退出登录？浏览不受影响，重新登录后记录仍在。」→ 清本地会话与内存缓存，回登录前态。无网络也可退出（仅本地）。

### 3.2 删除账户（App 内完成，含 Apple token 撤销）

流程：入口「删除账户」（红色行）→ **屏 1 后果清单**（见下）→ 「继续删除」→ **屏 2 二次确认**：输入框须键入「删除」二字激活红色确认按钮 → 处理中（不可取消，转圈+「正在删除账户…」）→ 完成/失败。

后果清单文案（冻结，逐条列出）：

- 「你的账号和登录方式将被删除，Apple 授权将同时撤销（我们会调用 Apple 的撤销接口）。」
- 「你发布的心愿的账号归属将被解除；已公开的心愿内容和进行中的订单按平台规则与法律要求继续处理或保留必要记录。」
- 「你的联系方式将从可用数据中删除；为处理纠纷与履行法定义务，交易与交付的必要凭证会在法定期限内留存后删除。」
- 「已完成的交付文件按订单约定处理；此操作不可恢复。」

状态：处理中=真实后端请求（撤销 Apple token → 删除/匿名化账号数据 → 返回结果）；失败=「删除未完成，你的账号未受影响」+重试（禁止本地假删除）；成功=「账户已删除」终态页 →「知道了」回到访客态首页。Apple token 撤销失败视为整体失败（撤销是法定必需步骤，不得静默跳过）。

## 4. 隐私边界（交付 4，冻结）

- 只使用 Apple 返回的 userID、姓名（首次）、邮箱（可能是隐藏中转邮箱）；**任何界面不展示邮箱**（包括隐藏邮箱），账户卡只显示昵称与"Apple 账号已连接"。
- 不请求手机号、通讯录、精确定位；联系方式字段继续标注"仅运营可见"，与登录体系完全隔离。
- 归属列表只对本人可见；他人经编号查询看到的内容不因账号存在而增加。
- 不做关注/私信/评论/点赞后端；互动仍是"功能准备中"诚实弹窗。

## 5. 逐屏规格与验收（交付 5）

屏清单（编号即验收截图清单，Simulator+真机各一套）：

- **A 登录说明片**（发布提交触发）：说明片+Apple 按钮+「暂不登录」；
- **B 登录说明片-失败态**：红字+重试；
- **C 我的-登录前**：访客卡含 Apple 按钮；
- **D 我的-登录后**：账户卡+两列表入口+找回+账户与安全；
- **E 我发布的-loaded**：真实状态徽章列表；**E2 空态**；
- **F 本人心愿详情**（免编号进入 ProgressView 结果态）；
- **G 找回历史心愿**：表单/失败/已被绑定/成功四态各一张；
- **H 退出确认弹窗**；
- **I 删除-后果清单**；**J 删除-二次确认（键入"删除"）**；**K 删除-处理中**；**L 删除-完成**；
- **M 凭证撤销横幅**（我的页一次性提示）。

无障碍要求：Apple 按钮用系统组件自带朗读；说明片、后果清单逐条为独立可朗读元素；键入「删除」输入框 `accessibilityLabel`「输入 删除 两个字以确认」；所有新按钮 ≥44pt；状态变化用 `accessibilityAnnouncement` 播报"已登录/删除完成"；红色仅与文字/图标并用不单独传义；Dynamic Type 全档不截断（用 token 字体，禁 `.system(size:)` 硬编码——延续 CL-008 P1-4 教训）。

状态总表：每个新屏均须实现 空/加载/失败/成功 + 取消回退；任何失败必须保留用户输入。

## 6. 工程分阶段顺序（交付 5 末项，供 Codex 开卡）

1. **阶段一（Worker+D1 架构/API）**：账号表（appleUserId 唯一键、昵称、创建/删除时间）、Sign in with Apple identityToken 服务端验证、会话签发；wishes/responses 增加可空 `userId` 归属列；找回绑定接口（编号+联系方式验证→绑定，唯一约束）；删除接口（Apple revoke → 匿名化/删除）。**先行，不动客户端。**
2. **阶段二（iOS 登录）**：Sign in with Apple capability、登录说明片、会话保持、凭证撤销检查、我的登录前/后两态。
3. **阶段三（归属列表）**：发布/响应提交携带会话；我发布的/我帮助的真实列表+详情复用。
4. **阶段四（迁移与删除）**：找回历史心愿；退出登录；删除账户全流程。
   每阶段独立任务卡、独立验收；阶段二起每张卡附本文件对应屏截图验收。

## 7. 官方约束假设与未决问题（交付 6）

假设（按 2026-01 前公开资料，实现前由工程复核当年要求）：App Store 审核要求提供第三方登录的 App 必须提供 Sign in with Apple（本设计仅 Apple 登录，满足）；提供账号创建的 App 必须支持 App 内删除账户且撤销 Apple token；姓名/邮箱仅首次授权返回；`Sign in with Apple` 按钮样式不得改色变形。

未决产品问题（需产品负责人裁决，不阻塞阶段一）：

1. 匿名「暂不登录」通道是否设时限（如 1.1 起发布强制登录）？本规格默认长期保留。
2. 删除账户后，已公开的完成故事（未来上线）是否随之下架？建议随删除一并下架，待故事 API 立项时定。
3. 昵称修改是否需要审核？建议先做长度/敏感词校验，不做人工审核。

未验证项：零代码零运行；Apple 面板真机行为、revoke 接口时延、D1 约束均待工程阶段验证；CL-008 两个 P0（搜索诚实空态、Dock VoiceOver）由 AG-012 处理，与本规格无冲突——AG-012 改动的 ProfileView 区块与本规格 §2 叠加时，以本规格 IA 为准合并。
